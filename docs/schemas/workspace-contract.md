# M2 workspace integration contract

- Workspace/journal/event versions are 1/1/2. `internal/runmodel/workspace.go` is authoritative for the manifest DTO. Required arrays are non-null; unknown quality/provenance/hash fields are null, not reassuring zeroes. M2 warns that quality and exact tool identities are not collected yet.
- `docs/schemas/journal-v1.schema.json` validates each NDJSON line, not a JSON array/header. UTF-8 without BOM, one Event v2 plus LF; seq starts at 1 and is contiguous per run. No synthetic cancellation after a crash.
- Persistence track owns `internal/workspace/{writer,journal,manifest,lock_windows,lock_other,recovery,paths}.go` and tests. Navigation track owns `navigation.go` and tests. `contracts.go` is shared preflight and stays unchanged without coordination.
- Persistence exports `Open(handle runmodel.RunHandle,spec runmodel.RunSpec) (*Writer,error)`, `(*Writer).Append(runmodel.Event) error`, `(*Writer).Snapshot() (runmodel.Workspace,error)`, `(*Writer).Close() error`. Writer satisfies Sink. `(*Writer).SetPublisher(func(runmodel.Workspace) error)` installs the navigation callback before the first event. No engine import in workspace.
- Open acquires an OS lifetime lock in `.morgue/run.lock`; ErrLocked wins over empty-directory inspection. Only empty output, ignoring scaffolding created for this admission, is accepted. Nonempty output returns ErrNotEmpty before journal/manifest publication; preserve existing content. Engine selects `<input-stem>-<runId>` child and retries Open. ErrLocked becomes engine.ErrOutputBusy. Close releases the lock even after a failed write.
- Open does not publish a zero-sequence manifest. Snapshot before the first successful append returns ErrNoEvents. The first append must be run.started with matching handle/spec. M2 creates `.morgue/tools.lock.json` as `{schemaVersion:1,complete:false,tools:[]}`.
- Append serializes writes and validates envelope version, run identity, contiguous sequence, one started/finished lifecycle. Unknown event types may be retained for forward-compatible projection; unsupported major versions fail. Write/Sync/replace errors poison Writer. Append failure must not advance Snapshot/lastSeq or notify clients; restore the pre-append journal boundary if publication fails, where storage permits. Never report successful completion after a durability error. Keep the previous readable manifest.
- Sync before publishing every snapshot's lastSeq. Publish snapshots for started/target discovery/target finish/artifact/quality/run finish; coalesce progress/log snapshots to at most once per second. Terminal append synchronously publishes manifest and invokes publisher before returning success. Publisher receives the same projection, never rebuilds it. Publisher I/O failure is surfaced, not hidden behind a successful run.
- TargetDiscovered gains optional `sha256`, `inputSet`, `startedAt`; TargetFinished gains optional `inputSet`, `files`. These extend Event v2 compatibly. Persistence copies them into TargetRecord; inputSet at finish replaces earlier inputSet when present. Set terminal finishedAt from the envelope and durationMs from payload. State is pending on discovery, running on step.progress, finished on target.finished. Quality remains null until quality.updated.
- Event payload target outputs may be absolute (M1 compatibility); manifest outputs/artifacts are slash-normalized relative to spec.Output. Empty output for an unexecuted target is allowed. Reject lexical and reparse/junction escapes. Only an explicit spec.GameDataOut may produce an absolute external artifact; mark external=true and do not clean/traverse it. Artifact records are upserted by id so a shared product is listed once.
- Recovery API: `Read(root string) (Recovery,error)`, `ReadEvents(root,runID string,after uint64,limit int) (EventPage,error)`, `RebuildManifest(root string) (Recovery,error)`. Read is non-mutating, returns projected valid prefix, LastSeq, Active, Interrupted, TornTail, Diagnostics. Only a torn final line may be ignored with a warning; interior corruption/sequence gaps/other run IDs return an error plus available prefix. Interrupted means no terminal event and no live OS lock. Rebuild requires exclusive lock and preserves the prior snapshot.
- ReadEvents is bounded to 1..1000 records/page, checks runID, exposes journal lastSeq and hasMore, and does not buffer the entire log. Readers must tolerate an actively appended final incomplete line. Navigation's authenticated service owns HTTP error mapping; the persistence layer never trusts arbitrary caller paths without containment checks.
- Navigation exports `WriteNavigation(ws runmodel.Workspace) error`; engine calls writer.SetPublisher(WriteNavigation) after Open. This creates root/target Markdown from the supplied snapshot. Recent-path persistence belongs to navigation; do it when handling a new run.started workspace, not on every progress line. No navigation function calls engine. App version/commit may be unknown in developer builds and must be labelled as such.
- Engine owns fresh-output choice, journal-before-notification ordering, terminal summary on error/cancellation, run-local shared product cache, actual file counts and input hash capture. Do not change engine/recipe files in persistence/navigation tracks. InputObserver.Record records late-consumed companions; final target event supplies the complete known inputSet. Unmeasurable consumed references are marked pending with an explicit warning, never reported hashed.
- `workspace.PhysicalPath(path)` exposes the platform-native existing-path resolver for producer containment checks (Windows junctions require a final-handle path, not filepath.EvalSymlinks). After validating physical containment, external artifact records retain the lexical absolute path through spec.GameDataOut so writer/reader link policies agree.
- Context.Artifacts optionally records successful recipe products via `Record(path,kind,stepID,tool string,shared bool) error`; shared products use a target-independent artifact id and appear once. Engine records partial products with complete=false after target failure. Explicit GameDataOut is resolved to a fresh `run-<runId>` child for every admission; this preserves prior external exports and separates concurrent CLI runs.
- Normal clients need no resume protocol: a new run always uses a fresh workspace. Recipes never trust `.ripped`, `.organized` or dump markers from a previous invocation. SharedProducts.Do is a same-live-run cache keyed by game identity/settings; only successful results are reusable.
